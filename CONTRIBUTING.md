# Suggesting a Library

Thanks for helping keep this list useful! This page explains what we add and why, so you know before opening a pull request whether your suggestion is likely to be accepted. The same rules apply to everyone, including maintainers and authors submitting their own projects.

## What we list

A suggestion needs all of the following:

- **Data visualization is its main purpose.** Tools that happen to include charts or graph views, such as databases, ontology editors or general IDEs, are out of scope.
- **Open source.** A public repository with an open-source license. Paid or closed-source products are not listed.
- **Something to look at.** A README with screenshots, a demo or examples, so readers can tell what it does.

## Stars and age

Stars aren't a measure of quality, but they're the most objective signal we have that other people have found a project useful. We use them so decisions don't come down to personal taste.

| GitHub stars | Outcome |
|---|---|
| 50 or more | Accepted when it meets the requirements above. |
| 20 to 49 | Accepted if the pull request explains what makes it notable (a unique niche, known users, active development) and the repository is at least 3 months old. |
| Fewer than 20 | Politely declined for now. You're very welcome to resubmit once it reaches 50 stars. |

Projects hosted outside GitHub are judged by comparable signals (downloads, citations, users).

## Your own projects

Self-promotion is fine: authors know their projects best. Please say in the pull request that you're the author, and expect the same bar as any other submission.

## Existing entries

Listed projects are reviewed with the same rules. Archived or long-inactive projects that remain useful are kept, while entries that no longer meet the bar may be removed.

## How to submit

- Check for duplicates first, both in the [README](README.md) and on [awesomedataviz.com](https://awesomedataviz.com).
- Use the format `- [Name](https://github.com/owner/repo) - Short description.` and link to the source repository.
- Keep descriptions short, simple and unbiased.
- Place the entry in alphabetical order in the right section, or add a new category if needed.
- One suggestion per commit.

The website is rebuilt from the README automatically; see [site/](site/) for how it works.
